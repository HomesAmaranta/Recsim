# recsim —— 推荐算法语义增强的用户模拟（KuaiRand-10W）

只模拟用户，不生成新视听内容（依据 `kuairand-10w/A-README.md` §4.3
「仅作参考，模拟不生成新视听内容」）。产出物按 §4.1 的 19 字段结构给模拟用户互动日志。

## 1 一句话结论

时间切分评测、200 用户 × 25 条 = **5,000 轮二选一**（一真一假，随机基线 50%）：

| 判决路径 | 准确率 | 95% 区间 |
|---|---|---|
| 语义路：LLM 多角度画像 + 长短期记忆（单向） | 0.7140 | [0.701, 0.726] |
| 语义路：A/B 双向去位置偏置（读 logprobs） | 0.7182 | [0.706, 0.731] |
| 统计路：成对 logistic + LLM 语义增强特征 | **0.8986** | [0.890, 0.907] |
| 融合（门控堆叠，最终交付） | 0.8980 | [0.889, 0.906] |

用户级：中位 0.920，98.5% 的用户 ≥75%，75.5% 的用户 ≥85%。

**中期 75% 指标达成，85% 亦达成。** 但必须与负采样协议一并说明，见 §5 诚实性声明；
融合的实测增量为零，原因诊断见 §4.5 与 §6 发现 6，不要把 0.898 说成「LLM 模拟出来的」。

## 3 跑法

```bash
python3 recsim/prep/01_select_users.py     # ~2.5 min（扫 2.8GB 日志）
python3 recsim/prep/02_extract_logs.py     # ~2 min
python3 recsim/prep/03_build_profiles.py   # ~1.5 min（200 次 LLM）
python3 recsim/sim/generate.py --dual      # ~8.5 min（5000 对 × A/B 双向 = 10000 次 LLM，19.8 req/s）
python3 recsim/sim/fuse.py                 # ~1 min（纯 numpy）
python3 recsim/eval/accuracy.py            # 秒级，读 out/decisions.jsonl
```

消融/变体（不影响主产物）：

```bash
# 小规模冒烟：3 用户 × 5 条
python3 recsim/sim/generate.py --smoke 3 5
# 关掉某个角度看掉多少点
python3 recsim/sim/generate.py --smoke 20 10 --angles short_term_memory=0 --tag a_nosm
python3 recsim/sim/fuse.py --tag a_nosm && python3 recsim/eval/accuracy.py --tag a_nosm
# 融合侧消融（纯 numpy，秒级，不重跑 LLM）
python3 recsim/sim/fuse.py --nosem     # 去掉 LLM 语义增强特征
python3 recsim/sim/fuse.py --noheat    # 去掉统计路热度捷径，看融合机制本身有没有增量
```

LLM 端点在 `config.py` 的 `LLM_ENDPOINT`（当前 Qwen3-30B-A3B-Instruct-2507，SGLang）。

## 4.5 融合方法（语义路 × 统计路）

两路在 `sim/fuse.py` 汇合。**v1（旧）** 是 `logit = a·margin_stat + b·L_llm`，`L_llm∈{+1,0,−1}`。
实测交叉拟合出 `b ≈ −0.02 / +0.16`，等于 LLM 没有发言权。原因诊断（全量 5,000 对）：

- 统计路错的 516 条里，LLM 只答对 215 条 = **0.4167，比抛硬币还差**。两路一致率 0.727。
- 根因：候选块注入了平台热度，而统计路的主导特征也是热度
  （`log_show_user +1.39 / log_show_cnt +1.06`，其余全部 ≤0.53）。**两路吃同一个捷径，共线。**

**v2（当前）** 从三个方向改，每一步都单独量化：

| 改动 | 机制 | 实测 |
|---|---|---|
| ① 正交化 | 融合用的语义通道关掉热度块（`--angles item_popularity=0`），故意让它变弱但独立 | LLM 单独 0.673→0.625，但一致率 0.685→0.603、统计路错时救回率 0.429→**0.629**、门控上限 0.950→0.968（同 400 对） |
| ② 去位置偏置 | A/B 互换各跑一次，取 `sA=(s1−s2)/2`，`s=logP(A)−logP(B)` 由 `logprobs` 读出，位置项在相减中抵消 | 位置偏置项实测 −1.61（模型偏 B）；选 A 率 0.380→**0.460**（真值 0.420）；准确率 0.6624→**0.6692**（全量 5,000 对，不额外花 token） |
| ③ 门控堆叠 | `logit = a₁·m + a₂·m|m| + b₁·L·g + b₂·tanh(s/4)·g`，`g=1/(1+(|m|/1.5)²)`。统计路越自信，LLM 越没发言权。全部特征都是 A↔B 互换下的奇函数，保证融合器自身不引入位置偏置；4 个系数按用户分 2 折交叉拟合 | 语义项合计 `b₁+b₂`=**+0.070**（统计项 `a₁`=+0.957，即语义路话语权是统计路的 7%）；等效票权重 `\|m\|=1` 时 +0.049、`\|m\|=6` 时 +0.004 |
| ④ 特征级融合 | 不让 LLM 投票，而是让它的**语义画像文本**变成特征（角度 12），在训练期与统计特征联合定权 | `sem_cat_pref` 单特征 2AFC 0.723（覆盖 2619/5000 对），联合拟合后权重 +0.27，统计路 0.8968→**0.8986** |

**结论（诚实版）：决策级融合在本协议下拿不到显著增量，特征级融合拿到 +0.18pt 但不显著。**
见 §6 发现 6，那里给了排除「实现问题」的三个反证。

> **完整推导、四个设计点为什么这么写、学出的权重表、共线性口径、
> 以及「不能做的诱惑」，见 [`FUSION.md`](FUSION.md)。**


## 5 评测协议（必须与准确率一起引用）

- **时间切分**：训练期 20220408–20220501 建画像/记忆/统计；测试期 20220502–20220508
  只做正样本来源。模拟器在建状态时看不到测试期任何一条记录。
- **正样本**：该用户测试期真实点击过的视频（同一视频去重）。
- **候选池**：`REQUIRE_CAPTION=True` —— 正、负样本一律只从**有标题**的 93,489 个视频里取
  （占全库 91.1%）。无标题视频占全库 8.9% 但只占真实点击 3.9%（比值 2.26×），
  本身构成一个与用户偏好无关的捷径；且正样本无标题时 LLM 拿不到任何内容信息
  （实测该子集 0.528 ≈ 抛硬币）。去掉后两侧同分布，LLM 路从 0.6772 升到 0.7102。
- **负样本**：`NEG_PROTOCOL="global_random"` —— 从上述有标题候选池均匀随机，
  排除该用户训练期+测试期出现过的任何 `video_id`。统计路构造训练对时用同一候选池。
- **位置**：A/B 随机化；报告里单列位置偏置检查（融合路选 A 率 0.499，无偏置）。
  语义路单向有明显偏 B（选 A 率 0.439），故另出一路 A/B 双向去偏，见 §4.5 ②。
- **判定**：一真一假二选一，答对即该条正确，**随机基线 50%**。
- **降噪只作用于训练期**，测试期保持原样作为真值。
- **统计路无泄漏**：权重只在训练期构造的二选一对上拟合（正=训练期点击，
  负=同一全库随机协议），且构造训练对时对正样本做**留一扣除**——否则正样本的标题
  会进入该用户自己的历史词表、类别计数含自身，`cap_overlap` 权重被推到 +4.9，
  训练对准确率虚高到 0.979 而测试期只有 0.797。修掉后测试期升到 0.892。
- **融合权重无泄漏**：`logit = a₁·m + a₂·m|m| + b₁·L·g + b₂·tanh(s/4)·g`（§4.5 ③），
  4 个系数按用户分 2 折**交叉拟合**——每个用户的权重都来自另一折用户，不用自己的数据。
  4 个特征全是 A↔B 互换下的奇函数，无常数项、无位置项，融合器自身不引入位置偏置。

### 诚实性声明：全库随机负采样是「易负样本」协议

正样本来自曝光日志，而推荐系统只投放有流量的视频；负样本来自全库，其中绝大多数是
冷视频。因此**视频热度本身就是强捷径**：实测单靠 `log(show_cnt)` 一个特征就有 0.90。

`out/report.md` §6 按正负样本热度差分桶，把这件事量化了：

| 热度差分桶 | 条数 | 融合准确率 |
|---|---|---|
| 正样本更冷 (Δ<−1) | 240 | 0.171 |
| 热度相近 (\|Δ\|<1) | 884 | 0.688 |
| 正样本较热 (1≤Δ<3) | 1698 | 0.976 |
| 正样本远热 (Δ≥3) | 2178 | 1.000 |

LLM 路同样吃这个捷径：候选块里注入「累计展示/触达用户」后 LLM 从 0.625 升到 0.673
（同 400 对消融）。热度相近子集上 LLM 只有 0.620。

所以：**0.8986 只在 `global_random` 协议下成立，不能与曝光内困难负样本的数字混用。**
热度相近子集（884 条，捷径失效）上的 0.688 更接近真实困难负样本的量级。
若验收方要求困难负样本，改 `config.NEG_PROTOCOL` 并重跑即可，届时数字会明显下降。

## 6 实测发现

1. **LLM 不擅长绝对判断，擅长相对判断。** 逐条预测「会不会点」时 LLM 只有 0.600，
   还不如全预测 0 的 0.725；二选一（相对）就能到 0.677。所以画像 prompt 里
   刻意不让它输出「点击倾向高/中/低」——真实 CTR 0.101 时它会说 "high"——
   所有绝对数值一律用统计量直接注入。
2. **开思维链反而掉 7.5 个点**（0.677 → 0.605）。模型一旦开始写理由，就转去评
   「内容好不好」而不是「这个人会不会看」。最终 `cot=False`。
3. **位置偏置必须显式压制。** 初版 15 条里 12 条选 A。在任务描述里加
   「A/B 顺序随机打乱、不携带信息、请先各自独立评估再比较」后，选 A 率回到 0.42–0.49。
4. **候选侧信息量是 LLM 路的第一瓶颈。** 用户侧 prompt ~1,900 token，候选侧初版只有
   2 行（类别 / 时长档 / 标题）约 60 token。补全成四级类别 + 作者交叉 + 上传/配乐/标签 +
   平台播放与互动率后，候选侧涨到 ~600 token，LLM 路 0.6772 → 0.7102。
   消融（同 400 对）：全开 0.6725；去掉平台侧表现块 0.6250（−4.8pt，含热度捷径）；
   整块去掉候选信息 0.5425（−13pt，接近抛硬币，说明用户画像单独几乎不可判）。
5. **角度消融（用户侧，各 200 条）**：全开 0.680；去短期记忆 0.655（−2.5pt，贡献最大）；
   去长期记忆 0.675；去群体特征 0.680（无贡献）；只留统计块、去掉 LLM 语义画像
   0.660（语义画像 +2pt）。
6. **融合的实测增量为零，且这不是实现问题。** 门控堆叠融合 0.8980 vs 统计路 0.8986
   （救回 20 / 拖累 23，McNemar p=0.76）；特征级语义增强 0.8968→0.8986
   （救回 35 / 拖累 26，p=0.31）。三个反证排除了「融合器写坏了」：
   - **信息确实存在**：把 5,000 对按 `|margin|` 分箱，每一箱内 LLM 票指向真值的比例
     都显著高于 0.5（z = +1.98 / +5.74 / +5.57 / +12.56 / +24.74），即条件于统计路
     打分，LLM 仍带信息，不是纯噪声。
   - **但信息被吞掉**：每一箱内 LLM 准确率都**低于**统计路，且错误集中在统计路也错的
     对上——统计路错的 507 条里 LLM 只对 198 条（0.3905，低于抛硬币）。所以最优权重
     必然很小（语义项合计 +0.070，vs 统计项 +0.957），可翻转的只有 `|m|<0.5` 的（占 8.5%）
     薄薄一层，那里统计路 0.550、LLM 0.537、救回率 0.517 —— 净收益结构性为零。
   - **拿掉捷径也一样**：`fuse.py --noheat` 把统计路的 `log_show_cnt/log_show_user`
     清零后统计路降到 0.7506、语义路 0.6692，融合 0.7494（救回 143 / 拖累 149，p=0.77）。
     两路一致率反而升到 0.704。二维格子扫描（`|margin|`×`|llm_score|` 共 20 格）
     只有 1 格 n=223 微弱反超，是噪声。

   一句话：**这个协议下两路在判同一件事（内容-用户匹配度），统计路做得更好；LLM 的
   增量要靠更强的语义信号（如真实语义向量检索、多轮状态推演），不是靠换加权公式。**
7. **A/B 双向去偏是不花钱的净收益。** 单向判决选 A 率 0.4386，真值在 A 时 0.6554 /
   在 B 时 0.7705——明显偏 B。互换 A/B 各跑一次取 `(s1−s2)/2` 后，选 A 率 0.5090，
   两侧 0.7324 / 0.7045，准确率 0.7140→0.7182。代价是 2× 判决调用，但输出仍是 1 token，
   且互换 prompt 与原 prompt 共享用户侧前缀，SGLang 前缀缓存命中，吞吐只从
   28 req/s 降到 19.8 req/s（10,000 次调用 505s）。
   位置偏置项实测均值 −1.61（对数几率尺度），这解释了之前 gpt-4o 对比里 Qwen 的
   「优势」有一部分只是它偏 B、而那批样本恰好 58% 真值在 B。
8. **冷启动是上限来源**：测试期 57.6% 的曝光落在训练期曝光数 <20 的视频上，
   物品 ID 先验不泛化，只有内容特征能泛化。

## 7 已知缺口

- `is_rand` 在全部 36.9M 行里恒为 0 —— 数据集里**没有无偏随机曝光子集**，
  所有评测都在既有推荐策略的曝光集合上做；导向性漏洞挖掘缺反事实数据。
  建议追加 KuaiRand 的 `log_random_*.csv`。
- 真实用户只有 24,292 个，中期 50 万用户目标需约 20× 聚类式扩增
  （新用户 `user_id` 建议走 ≥1,000,000 号段与真实用户区分）。
- 角度 8/9/10（自我校准 / 群体冲突调节 / 状态更新闭环）只留了开关未实现，
  这三个要在多轮推演场景才有意义。
